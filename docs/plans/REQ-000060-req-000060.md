### TASK-001 — Streamed transcript wrapper (`session_transcript.sh`)

- **Description.** Implement `run_streamed_session(...)` per TDD §4.2:
  a bash wrapper that composes `timeout` → `stdbuf -oL -eL` → `bash
  spawn-session.sh ...` piped through `tee -a "${output_file}" >
  /dev/null`, returning `PIPESTATUS[0]`. Detect `gstdbuf` vs `stdbuf`
  and gracefully degrade to tee-only when neither is present
  (ADR-002 fallback). Bash 3.2 safe (macOS system bash) — use the
  `runner=(...)` array pattern used elsewhere in the plugin.
- **Files.**
  - CREATE `plugins/autonomous-dev/lib/observability/session_transcript.sh`
  - CREATE `plugins/autonomous-dev/tests/bats/session_transcript_streamed.bats`
  - CREATE `plugins/autonomous-dev/tests/bats/fixtures/fake-agents/emit-then-hang.sh`
    (used by later E2E tests too; small fixture per OQ-3)
- **Dependencies.** None (root of Track A).
- **Acceptance Criteria.**
  1. Sourcing `session_transcript.sh` exposes `run_streamed_session`.
  2. Running `run_streamed_session` against a fake agent that prints
     `line1`, sleeps 3 s, prints `line2` shows `output_file` size > 0
     with `line1` present at T+1 s (BEFORE the child exits) — the
     0-byte-on-hang regression.
  3. When neither `stdbuf` nor `gstdbuf` is present (mocked via
     `PATH=/dev/null`), the wrapper still runs and the transcript is
     still non-empty on hang.
  4. `PIPESTATUS[0]` (child exit) is returned; the tee side is ignored.
- **Lint/Test Commands.**
  - `bats plugins/autonomous-dev/tests/bats/session_transcript_streamed.bats`
  - `shellcheck plugins/autonomous-dev/lib/observability/session_transcript.sh`
- **Estimated Effort.** 3.0 h (impl ~1.5 h, tests ~1.0 h, buffer 0.5 h)
- **Track.** A (transcript & heartbeat)
- **Risks.**
  - *Medium — coreutils absence on lean CI images.* Mitigation:
    fallback path is exercised by test #3 above; document in T9 runbook.
  - *Low — bash 3.2 array-append edge cases.* Mitigation: follow the
    existing `spawn-session.sh` §227 pattern verbatim.

### TASK-002 — Phase baselines store (`phase_baselines.sh`)

- **Description.** Implement `phase_baselines_record(phase, elapsed_ms,
  exit_code)` and `phase_baselines_read(phase)` per TDD §4.5. Rolling
  window of the last 200 samples per phase; ignore-124 rule; atomic
  `tmp + rename` write with `mode 0600`; lock via `set -o noclobber`
  on `phase-baselines.json.lock`. Compute p50/p95/mean/sample_count on
  each record. Initial file creation is lazy — read of a missing file
  returns `{}`.
- **Files.**
  - CREATE `plugins/autonomous-dev/lib/observability/phase_baselines.sh`
  - CREATE `plugins/autonomous-dev/tests/bats/phase_baselines_rolling_update.bats`
- **Dependencies.** None (root of Track B — pure state utility).
- **Acceptance Criteria.**
  1. First `phase_baselines_record` creates
     `~/.autonomous-dev/state/observability/phase-baselines.json`
     with mode `0600`, parent dir `0700`.
  2. Feeding 300 samples results in `samples_ms.length == 200` for
     that phase (cap enforced).
  3. `p50_ms` and `p95_ms` match a jq-computed reference over the
     stored samples within ±5%.
  4. `exit_code == 124` samples are dropped (do not appear in
     `samples_ms`).
  5. `phase_baselines_read("unknown-phase")` returns `{}` without error.
  6. Corrupt JSON on read is renamed to
     `phase-baselines.json.corrupt-<ts>`; a fresh baseline is written.
  7. Concurrent invocations serialize via the lock file; no lost
     writes across two rapid records.
- **Lint/Test Commands.**
  - `bats plugins/autonomous-dev/tests/bats/phase_baselines_rolling_update.bats`
  - `shellcheck plugins/autonomous-dev/lib/observability/phase_baselines.sh`
- **Estimated Effort.** 2.5 h (impl ~1.0 h, tests ~1.0 h, buffer 0.5 h)
- **Track.** B (detector inputs)
- **Risks.**
  - *Low — jq p50/p95 arithmetic edge cases with < 5 samples.*
    Mitigation: assert `sample_count` guard in tests.
  - *Low — lock file left behind on kill.* Mitigation: `trap EXIT`
    to remove; also test the "stale lock older than 60 s" cleanup.

### TASK-003 — Heartbeat sidecar (`session_heartbeat.sh`)

- **Description.** Implement `heartbeat_start(...)` and
  `heartbeat_stop(...)` per TDD §4.3. Background subshell loop:
  every `AUTONOMOUS_DEV_HB_INTERVAL_S` (default 15) seconds, stat
  the output_file, compute delta_bytes and silent_seconds, atomically
  write `session-progress.json` (schema §5.4), then invoke the
  detector (see TASK-004 — during T2 the detector is a stub that
  always returns `ok`; T4 replaces it with the real one). Terminate
  on SIGTERM (delivered by `heartbeat_stop`).
- **Files.**
  - CREATE `plugins/autonomous-dev/lib/observability/session_heartbeat.sh`
  - CREATE `plugins/autonomous-dev/tests/bats/session_heartbeat_progress.bats`
- **Dependencies.** TASK-001 (test uses the streamed transcript).
- **Acceptance Criteria.**
  1. `heartbeat_start` returns a pid; that pid writes at least 3
     samples in a 5 s test window with `AUTONOMOUS_DEV_HB_INTERVAL_S=1`.
  2. Each sample validates against `session-progress.json` schema
     (§5.4) — required keys: `schema_version`, `request_id`, `phase`,
     `session_pid`, `started_at`, `ts`, `elapsed_ms`, `transcript`,
     `status`.
  3. `elapsed_ms` and `transcript.bytes` are monotonically
     non-decreasing across samples.
  4. `heartbeat_stop` writes a final sample with `status: "exited"`
     and returns within 500 ms.
  5. Environment overrides for `AUTONOMOUS_DEV_HB_INTERVAL_S` take
     precedence over the default.
  6. Sidecar exits when parent subshell exits (test kills parent,
     asserts sidecar pid is gone within 2 s).
- **Lint/Test Commands.**

  - `shellcheck plugins/autonomous-dev/lib/observability/session_heartbeat.sh`

- **Track.** A

  - *Medium — subshell `trap EXIT` reliability on macOS bash 3.2.*

  - *Low — torn read of `session-progress.json` in other readers.*
    Mitigation: atomic tmp+rename; TDD §3.4 already documents the

### TASK-004 — Hung-session detector (`hung_session_detector.sh`)

- **Description.** Implement pure `detect_hung(sample_json,
  baselines_json, cfg_json)` per TDD §4.4. No file I/O — reads three
  arguments, emits verdict JSON on stdout: `{"verdict": "ok" |
  "suspected", "reason": "silent_stall" | "elapsed_over_p95",
  "evidence": {...}}`. Silent-stall triggers when
  `transcript.silent_seconds >= cfg.silent_stall_s`;
  `elapsed_over_p95` triggers when
  `elapsed_ms / baselines.p95_ms >= cfg.anomaly_multiplier` AND
  `baselines.sample_count >= cfg.min_baseline_samples`.
- **Files.**
  - CREATE `plugins/autonomous-dev/lib/observability/hung_session_detector.sh`
  - CREATE `plugins/autonomous-dev/tests/bats/hung_session_detector_anomaly.bats`
- **Dependencies.** TASK-002 (baseline schema), TASK-003 (sample schema).
- **Acceptance Criteria.** Table-driven bats (per TDD §8.1):
  1. `elapsed=1000, p95=100000, silent=0, threshold=3.0` → `ok`.
  2. `elapsed=350000, p95=100000, silent=0, threshold=3.0` →
     `suspected/elapsed_over_p95`.
  3. `elapsed=1000, p95=100000, silent=400, stall=300` →
     `suspected/silent_stall`.
  4. `elapsed=350000, p95=null (0 samples), silent=0` → `ok`
     (baseline cold, `sample_count < min_baseline_samples`).
  5. Pure function: repeated invocations with identical inputs
     produce byte-identical stdout.
  6. Detector does not touch the filesystem (asserted by running
     under a strace-lite wrapper or, on macOS, by giving it a
     read-only chroot-style CWD).
- **Lint/Test Commands.**
  - `bats plugins/autonomous-dev/tests/bats/hung_session_detector_anomaly.bats`
  - `shellcheck plugins/autonomous-dev/lib/observability/hung_session_detector.sh`
- **Estimated Effort.** 2.0 h (impl ~0.75 h, tests ~1.0 h, buffer 0.25 h)
- **Track.** B
- **Risks.**
  - *Low — silent-stall vs elapsed-over-p95 precedence when both fire.*
    Mitigation: fix precedence in TDD (silent_stall first — added to
    test #7 as a fifth row: both fire → `silent_stall`).
